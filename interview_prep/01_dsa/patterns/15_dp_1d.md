# 15 - Dynamic Programming - 1D
> When the answer at index `i` depends only on a constant number of earlier answers, build a single linear array (or a few rolling variables) instead of recomputing.

## When to use it (recognition triggers)
- The problem asks for "number of ways", "min/max cost", "longest/shortest", or "can you reach" over a 1D sequence (array, string, or a count like `n`).
- A naive recursion `f(i)` calls `f(i-1)`, `f(i-2)`, ... and you see the same subproblems recomputed (overlapping subproblems).
- The optimal answer is built from optimal answers to smaller prefixes/suffixes (optimal substructure).
- You can phrase the choice at each step as "take it or skip it" / "extend or restart" / "split here or not".
- Constraints are linear-ish (n up to 10^4-10^6) and a brute-force/exponential recursion would TLE.
- The transition only ever looks back a fixed distance (often 1 or 2), hinting you can drop the array down to O(1) rolling variables.

## Mental model
- Define `dp[i]` = the answer for the subproblem ending at (or starting at) position `i`. The whole game is choosing this definition so the transition is clean.
- Write the recurrence: express `dp[i]` purely in terms of strictly smaller indices. This is the same recursion you'd write top-down, just filled bottom-up.
- Nail the base cases (`dp[0]`, sometimes `dp[1]`) and the iteration direction (left-to-right vs right-to-left).
- Memoization (top-down) and tabulation (bottom-up) are the same DAG of subproblems evaluated in different orders; tabulation usually lets you compress space.
- If `dp[i]` only reads `dp[i-1]` and `dp[i-2]`, you don't need the array — keep two variables and roll them. That's the O(1)-space "constant window" trick.

## Reusable template(s)
```python
# Bottom-up 1D DP skeleton (tabulation)
def dp_1d(nums):
    n = len(nums)
    if n == 0:
        return 0
    dp = [0] * (n + 1)        # size + base offset to avoid index < 0 checks
    dp[0] = base_case_0       # answer for empty / first state
    for i in range(1, n + 1):
        # dp[i] derived ONLY from dp[i-1], dp[i-2], ... and nums[i-1]
        dp[i] = transition(dp[i - 1], dp[i - 2], nums[i - 1])
    return dp[n]

# Same thing, O(1) space when the window is fixed (looks back 2 steps)
def dp_1d_rolling(nums):
    prev2, prev1 = base0, base1
    for x in nums:
        cur = transition(prev1, prev2, x)
        prev2, prev1 = prev1, cur
    return prev1
```

## Complexity profile
- Typical: **Time O(n)** (one pass, sometimes O(n*k) or O(n^2) when each state scans earlier states), **Space O(n)** for the table, compressible to **O(1)** when the transition window is constant.
- You're beating the naive exponential recursion (e.g., O(2^n) for "take/skip" or Fibonacci-style branching).

## Curated problems (easy -> hard)

### 1. Climbing Stairs  -  Easy
- **Problem:** You climb a staircase of `n` steps taking 1 or 2 steps at a time; count the distinct ways to reach the top.
- **Practice (free):** https://leetcode.com/problems/climbing-stairs/
- **Video (free):** https://neetcode.io/problems/climbing-stairs
- **Idea:** Ways to reach step `i` = ways to reach `i-1` (then +1) plus ways to reach `i-2` (then +2). It's Fibonacci.
```python
def climbStairs(n: int) -> int:
    # prev2 = ways to step (i-2), prev1 = ways to step (i-1)
    prev2, prev1 = 1, 1            # one way to stand at step 0 and step 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1
```
- **Complexity:** Time O(n), Space O(1)
- **Key insight / gotcha:** Base cases `f(0)=f(1)=1` (not 0). Off-by-one here breaks everything downstream.
- **Follow-up:** "What if you can take 1..k steps?" -> `dp[i] = sum(dp[i-j] for j in 1..k)`, or keep a sliding window sum for O(n).

### 2. Min Cost Climbing Stairs  -  Easy
- **Problem:** Each step `i` has a cost `cost[i]`; you start before index 0 or 1 and may climb 1 or 2 steps. Return the minimum cost to reach the top (past the last index).
- **Practice (free):** https://leetcode.com/problems/min-cost-climbing-stairs/
- **Video (free):** https://neetcode.io/problems/min-cost-climbing-stairs
- **Idea:** Cost to stand "on top of" step `i` is `cost[i]` plus the cheaper of the two prior arrival costs. The top is one past the end, so it costs 0 to be there.
```python
from typing import List

def minCostClimbingStairs(cost: List[int]) -> int:
    # prev2/prev1 = min cost to reach the step 2 back / 1 back
    prev2, prev1 = 0, 0           # free to start at step 0 or step 1
    for i in range(2, len(cost) + 1):
        cur = min(prev1 + cost[i - 1], prev2 + cost[i - 2])
        prev2, prev1 = prev1, cur
    return prev1
```
- **Complexity:** Time O(n), Space O(1)
- **Key insight / gotcha:** The "top" is index `n` (one beyond the last step), so you loop to `n` inclusive. Starting at 0 or 1 is free; the cost is paid when you *step off* a stair.
- **Follow-up:** "Reconstruct the path taken." -> Store back-pointers (which of the two predecessors won) and walk backwards from `n`.

### 3. House Robber  -  Medium
- **Problem:** Given a row of houses with money `nums[i]`, maximize the loot without robbing two adjacent houses.
- **Practice (free):** https://leetcode.com/problems/house-robber/
- **Video (free):** https://neetcode.io/problems/house-robber
- **Idea:** At each house choose max(skip it = `prev1`, rob it = `prev2 + nums[i]`). Classic take/skip with a 2-step look-back.
```python
from typing import List

def rob(nums: List[int]) -> int:
    prev2, prev1 = 0, 0           # best loot up to i-2, up to i-1
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1
```
- **Complexity:** Time O(n), Space O(1)
- **Key insight / gotcha:** `prev2 + x` uses the value from *two* houses back (the last legal non-adjacent state), not the immediate previous. Doing the rolling update in one line keeps the ordering correct.
- **Follow-up:** "Houses in a circle" -> House Robber II (next problem). "What if you can't rob two houses within distance k?" -> look back `k+1`.

### 4. House Robber II  -  Medium
- **Problem:** Same as House Robber, but the houses are arranged in a circle, so the first and last are adjacent.
- **Practice (free):** https://leetcode.com/problems/house-robber-ii/
- **Video (free):** https://neetcode.io/problems/house-robber-ii
- **Idea:** A circle means you can't rob both house 0 and house n-1. Run the linear robber twice: once excluding the last house, once excluding the first, and take the max.
```python
from typing import List

def rob(nums: List[int]) -> int:
    if len(nums) == 1:
        return nums[0]

    def rob_line(houses: List[int]) -> int:
        prev2, prev1 = 0, 0
        for x in houses:
            prev2, prev1 = prev1, max(prev1, prev2 + x)
        return prev1

    # either drop the first house or drop the last; first & last can't both be robbed
    return max(rob_line(nums[1:]), rob_line(nums[:-1]))
```
- **Complexity:** Time O(n), Space O(1) (the slices are O(n) memory; iterate with index ranges to get true O(1))
- **Key insight / gotcha:** Handle the single-house case before slicing, otherwise both slices are empty and you return 0 instead of `nums[0]`.
- **Follow-up:** "Avoid the O(n) slice memory." -> Pass `start`/`end` indices into `rob_line` and iterate over the range instead of slicing.

### 5. Decode Ways  -  Medium
- **Problem:** A string of digits maps to letters via A=1..Z=26; count how many ways it can be decoded.
- **Practice (free):** https://leetcode.com/problems/decode-ways/
- **Video (free):** https://neetcode.io/problems/decode-ways
- **Idea:** `dp[i]` = ways to decode the prefix of length `i`. Add `dp[i-1]` if the single digit `s[i-1]` is valid (1-9), and add `dp[i-2]` if the two-digit `s[i-2:i]` is in 10-26.
```python
def numDecodings(s: str) -> int:
    if not s or s[0] == '0':
        return 0
    prev2, prev1 = 1, 1           # dp[0]=1 (empty), dp[1]=1 (first char already validated)
    for i in range(1, len(s)):
        cur = 0
        if s[i] != '0':                       # single-digit decode 1..9
            cur += prev1
        two = int(s[i - 1:i + 1])             # two-digit decode 10..26
        if 10 <= two <= 26:
            cur += prev2
        if cur == 0:                          # dead end, e.g. "30" or leading 0 in a pair
            return 0
        prev2, prev1 = prev1, cur
    return prev1
```
- **Complexity:** Time O(n), Space O(1)
- **Key insight / gotcha:** `'0'` is the trap. A `'0'` is only decodable as part of "10" or "20"; "0", "30", "01" are all invalid. If `cur` hits 0 mid-string you can early-return 0.
- **Follow-up:** "Decode Ways II with `*` wildcards (0-9)" -> same skeleton but each transition multiplies by the count of digits the `*` can represent (9 for single, varying for pairs).

### 6. Coin Change  -  Medium
- **Problem:** Given coin denominations and a target `amount`, return the fewest coins that sum to it, or -1 if impossible (unlimited supply of each coin).
- **Practice (free):** https://leetcode.com/problems/coin-change/
- **Video (free):** https://neetcode.io/problems/coin-change
- **Idea:** `dp[a]` = min coins to make amount `a`. For each amount, try every coin: `dp[a] = min(dp[a - coin] + 1)`. Unbounded knapsack flavored as a min.
```python
from typing import List

def coinChange(coins: List[int], amount: int) -> int:
    INF = amount + 1                          # sentinel larger than any real answer
    dp = [0] + [INF] * amount                 # dp[0] = 0 coins for amount 0
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
```
- **Complexity:** Time O(amount * len(coins)), Space O(amount)
- **Key insight / gotcha:** Use `amount + 1` as infinity (you can never need more than `amount` coins of value >=1), which avoids `float('inf')` arithmetic and keeps comparisons clean. Greedy (always take the largest coin) is WRONG for arbitrary denominations.
- **Follow-up:** "Count the number of ways instead of the minimum" -> Coin Change II: `dp[a] += dp[a-c]`, but loop coins on the OUTSIDE to avoid counting permutations as distinct combinations.

### 7. Maximum Product Subarray  -  Medium
- **Problem:** Find the contiguous subarray with the largest product and return that product.
- **Practice (free):** https://leetcode.com/problems/maximum-product-subarray/
- **Video (free):** https://neetcode.io/problems/maximum-product-subarray
- **Idea:** Unlike max-sum, a negative number can flip the smallest product into the largest, so track BOTH the running max and running min ending at `i`. At each step the new candidates are `x`, `max*x`, `min*x`.
```python
from typing import List

def maxProduct(nums: List[int]) -> int:
    res = cur_max = cur_min = nums[0]
    for x in nums[1:]:
        # x alone (restart), or extend the previous max/min product
        candidates = (x, cur_max * x, cur_min * x)
        cur_max, cur_min = max(candidates), min(candidates)
        res = max(res, cur_max)
    return res
```
- **Complexity:** Time O(n), Space O(1)
- **Key insight / gotcha:** You MUST recompute `cur_max` and `cur_min` from the SAME pre-update values. Update them simultaneously (compute both from the tuple) or stash the old `cur_max` before overwriting it. A zero resets the window via the `x` candidate.
- **Follow-up:** "Maximum sum subarray" -> Kadane's: drop the min tracking, `cur = max(x, cur + x)`. It's the additive cousin of this problem.

### 8. Word Break  -  Medium
- **Problem:** Given a string `s` and a dictionary of words, determine whether `s` can be segmented into a space-separated sequence of dictionary words.
- **Practice (free):** https://leetcode.com/problems/word-break/
- **Video (free):** https://neetcode.io/problems/word-break
- **Idea:** `dp[i]` = can the prefix of length `i` be segmented. `dp[i]` is True if some `dp[j]` is True and `s[j:i]` is a word. It's a reachability DP over prefix boundaries.
```python
from typing import List

def wordBreak(s: str, wordDict: List[str]) -> bool:
    words = set(wordDict)                     # O(1) membership
    n = len(s)
    dp = [False] * (n + 1)
    dp[0] = True                              # empty prefix is trivially segmentable
    for i in range(1, n + 1):
        for j in range(i):
            if dp[j] and s[j:i] in words:     # split at j: [0..j) segmented, [j..i) is a word
                dp[i] = True
                break
    return dp[n]
```
- **Complexity:** Time O(n^2 * L) where L is avg word length for slicing/hash (O(n^3) loosely), Space O(n)
- **Key insight / gotcha:** Convert the dictionary to a `set` first, or membership checks dominate the runtime. The `break` after setting `dp[i]` is a small but real prune.
- **Follow-up:** "Return all sentences" -> Word Break II: switch to memoized backtracking returning lists; pure DP-boolean isn't enough to reconstruct all splits efficiently.

### 9. Longest Increasing Subsequence  -  Medium
- **Problem:** Return the length of the longest strictly increasing subsequence (not necessarily contiguous).
- **Practice (free):** https://leetcode.com/problems/longest-increasing-subsequence/
- **Video (free):** https://neetcode.io/problems/longest-increasing-subsequence
- **Idea:** The O(n^2) DP is `dp[i] = 1 + max(dp[j])` for `j < i` with `nums[j] < nums[i]`. The O(n log n) trick keeps a `tails` array where `tails[k]` is the smallest possible tail of an increasing subsequence of length `k+1`; binary-search each new value in.
```python
from typing import List
from bisect import bisect_left

def lengthOfLIS(nums: List[int]) -> int:
    tails = []                                # tails[k] = smallest tail of an LIS of length k+1
    for x in nums:
        i = bisect_left(tails, x)             # first tail >= x
        if i == len(tails):
            tails.append(x)                   # x extends the longest subsequence
        else:
            tails[i] = x                      # x gives a smaller tail for that length
    return len(tails)
```
- **Complexity:** Time O(n log n), Space O(n)
- **Key insight / gotcha:** `tails` is NOT an actual subsequence; its length is the answer. Use `bisect_left` for STRICTLY increasing; switch to `bisect_right` if non-strict (allow equal) increasing is required.
- **Follow-up:** "Reconstruct the actual subsequence" or "count the number of LIS" -> need the O(n^2) `dp` array (plus a parent/count array); the patience-sorting version only yields the length.

### 10. Palindromic Substrings (count)  -  Medium
- **Problem:** Count how many substrings of `s` are palindromes (each distinct start/end position counts, single chars included).
- **Practice (free):** https://leetcode.com/problems/palindromic-substrings/
- **Video (free):** https://neetcode.io/problems/palindromic-substrings
- **Idea:** Expand around each of the `2n-1` centers (n single-char centers + n-1 between-char centers). Every successful expansion is one more palindrome. This is the O(n^2)/O(1)-space approach that's cleaner than the 2D table.
```python
def countSubstrings(s: str) -> int:
    n = len(s)
    count = 0

    def expand(left: int, right: int) -> None:
        nonlocal count
        while left >= 0 and right < n and s[left] == s[right]:
            count += 1                        # s[left..right] is a palindrome
            left -= 1
            right += 1

    for i in range(n):
        expand(i, i)                          # odd-length center
        expand(i, i + 1)                      # even-length center
    return count
```
- **Complexity:** Time O(n^2), Space O(1)
- **Key insight / gotcha:** Don't forget the even-length centers `(i, i+1)` — missing them undercounts every even palindrome. Each char alone is a palindrome, so the minimum answer is `n`.
- **Follow-up:** "Do it in O(n)" -> Manacher's algorithm computes the palindrome radius at every center in linear time; it's worth knowing the name even if you rarely code it live.

### 11. Longest Palindromic Substring  -  Medium
- **Problem:** Return the longest contiguous substring of `s` that is a palindrome.
- **Practice (free):** https://leetcode.com/problems/longest-palindromic-substring/
- **Video (free):** https://neetcode.io/problems/longest-palindromic-substring
- **Idea:** Same expand-around-center engine as the count version, but instead of counting, track the longest `[start, end]` window seen across all expansions.
```python
def longestPalindrome(s: str) -> str:
    if not s:
        return ""
    start, end = 0, 0                         # best window [start, end]

    def expand(left: int, right: int) -> None:
        nonlocal start, end
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        # loop overshot by one on each side; real palindrome is (left+1 .. right-1)
        if (right - 1) - (left + 1) > end - start:
            start, end = left + 1, right - 1

    for i in range(len(s)):
        expand(i, i)                          # odd-length
        expand(i, i + 1)                      # even-length
    return s[start:end + 1]
```
- **Complexity:** Time O(n^2), Space O(1)
- **Key insight / gotcha:** After the `while` loop, `left` and `right` have each stepped one past the valid palindrome, so the true bounds are `left+1` and `right-1`. Compare lengths with that correction or you'll be off by two.
- **Follow-up:** "Why not the 2D `dp[i][j]` table?" -> It also works (O(n^2) time) but costs O(n^2) space; expand-around-center is the same time at O(1) space, so prefer it. For O(n), cite Manacher's.
